Vantage documentation

Agent use

Vantage can be driven by a trusted local agent through the same live browser session you use yourself. The agent sees and controls real Vantage windows and tabs rather than launching a separate automation browser.

Current agent surface

The first agent-native implementation provides stable window and tab identities, a versioned local RPC and CLI, live navigation, arbitrary page JavaScript, semantic page snapshots and interaction, screenshots and content inspection, broad WebKit property/settings introspection, and access to Vantage-owned downloads, bookmarks, history, permissions, cookies and profile state.

Human and agent share one browser

Selecting or navigating a tab through the agent API changes the normal visible Vantage browser. You can watch the work, use the browser at the same time, and take over normally. Closed object IDs and stale semantic element references are not silently reused.

Trust model

Vantage assumes the local agent is deliberately trusted with the user's machine authority. That does not extend the same trust to websites. The agent controls WebKit from the Vantage application side; ordinary page JavaScript remains inside WebKit's normal web security and process boundaries.

Agent reference

The website has a deliberately exhaustive Agent reference written for agents and integration authors. Human documentation stays focused on concepts, common commands and practical workflows; the agent reference carries exact RPC behavior, method names and lifecycle rules.

Vantage Browser is built in the open for Linux.
